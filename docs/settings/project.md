# Project: folder, conventions, roles of your own

A project is one folder with its own data, settings, context, results and container. labpipe finds it from the folder you run it in (the nearest parent holding `labpipe.yaml`). Updates replace the code, never your project.

```bash
labpipe project new ~/labpipe-projects/<name> --data ~/labdata/<folder> [--data ...] [--name NAME]
labpipe project sync          # after a labpipe update, or a change in lab/
```

- `project new` refuses a synced folder (Dropbox, OneDrive, Google Drive, iCloud, Nextcloud, ownCloud, Koofr, Syncthing, MEGA, Seafile) and a non-empty folder that is not a project. It creates `labpipe.yaml`, `config/local.yaml` (the data folders; the agents block from `~/.config/labpipe/defaults.yaml`, else the example's), `config/lab.yaml`, `config/samples.yaml`, `lab/LAB.md`, `lab/agents/README.md`, then runs `project sync`. It never overwrites a file.
- `project sync` writes the generated files: `AGENTS.md`, `CLAUDE.md`, `.labpipe/` (a read-only copy of the docs, default settings, `methods.yaml`, references and roles that agents read), `.claude/*.json`, `.codex/`, `.agents/`, and the harness's agent files. Each starts with "Generated by labpipe …. Do not edit". Agents cannot write them.
- `labpipe doctor` shows the project, its mode and whether the generated files are current. In the labpipe repository itself (dev mode) the repository is its own project and `project sync` writes only the agent files.

## You say → setting

| You say | Do |
|---|---|
| "we call the support Vulcan", "answer in Croatian" | a sentence in `lab/LAB.md` (added to the end of `AGENTS.md` and `CLAUDE.md`), then `labpipe project sync` |
| "the XRD analyst should always give Å" | `lab/agents/xrd-analyst.md`: plain sentences, appended to that role |
| "add our own XRD reference phase" | `labpipe xrd refs add file.cif --id NAME --structure-type …`: kept in `lab/references/xrd/` (docs/methods/xrd.md → Reference phases) |
| "we need our own agent role" | `lab/agents/<name>.md` starting with frontmatter (`name`, `role`, `description`, `capabilities`); see `lab/agents/README.md` |
| "a second project" | `labpipe project new <another folder>`: its own settings, results, container and port |

Text inside `<!-- … -->` in these files is left out (the templates keep their explanations and examples there). A file in `lab/agents/` that names no role (a typo) is reported by `labpipe project sync` and `labpipe doctor`, never dropped silently.

## After a change

`labpipe project sync`. Nothing is re-analysed. The agent tool picks up the new text in its next session.
