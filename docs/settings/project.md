# Project: folder, conventions, roles of your own

A project is one folder with its own data, settings, context, results and container. labpipe finds it from the folder you run it in (the nearest parent holding `labpipe.yaml`). Updates replace the code, never your project.

```bash
labpipe project new ~/labpipe-projects/<name> --data ~/labdata/<folder> [--data ...] [--name NAME]
labpipe project sync          # after a change in lab/ (`labpipe update` does it itself)
```

- `project new` refuses a data folder that is, contains or lies inside the project folder (data and project must be apart; `labpipe doctor` reports it, the container refuses to start), a synced folder (Dropbox, OneDrive, Google Drive, iCloud, Nextcloud, ownCloud, Koofr, Syncthing, MEGA, Seafile) and a non-empty folder that is not a project. It creates `labpipe.yaml`, `config/local.yaml` (the data folders, also as `protected_paths` so agents on this computer stay out of them; the agents block and the container engine and pop-ups from `~/.config/labpipe/defaults.yaml`, which the installer writes; without it the example's agents block and no container), `config/lab.yaml`, `config/samples.yaml`, `lab/LAB.md`, `lab/agents/README.md`, then runs `project sync`. It never overwrites a file.
- `project sync` writes the generated files: `AGENTS.md`, `CLAUDE.md`, `.labpipe/` (a read-only copy of the docs, default settings, `methods.yaml`, references and roles that agents read), `.claude/*.json`, `.codex/`, `.agents/`, and the harness's agent files. Each starts with "Generated by labpipe …. Do not edit". Agents cannot write them.
- `lab/` is yours and updates never touch it. Besides `LAB.md` and `agents/` it holds the lab's own analysis methods: `lab/methods.yaml` (the registry entries, same form as labpipe's `methods.yaml`) and `lab/methods/<name>/` (a Python package; its modules are imported as `labpipe_lab.<name>`). A lab method may not reuse a shipped method's name; its file patterns are tried after the shipped ones. `project sync` tells the agents where they and their pages are (`AGENTS.md` → "This lab's own methods"). Keep `lab/` in your backup or in git. In the container they run with the image's packages (numpy, scipy, matplotlib, Pillow, PyYAML).
- `labpipe doctor` shows the project, its mode and whether the generated files are current. In the labpipe repository itself (dev mode) the repository is its own project and `project sync` writes only the agent files.

## You say → setting

| You say | Do |
|---|---|
| "we call the support Vulcan", "answer in Croatian" | a sentence in `lab/LAB.md` (added to the end of `AGENTS.md` and `CLAUDE.md`), then `labpipe project sync` |
| "the XRD analyst should always give Å" | `lab/agents/xrd-analyst.md`: plain sentences, appended to that role |
| "add our own XRD reference phase" | `labpipe xrd refs add file.cif --id NAME --structure-type …`: kept in `lab/references/xrd/` (docs/methods/xrd.md → Reference phases) |
| "we want to analyse a technique labpipe has no method for" | `labpipe methods new <name> --example FILE --description TEXT`: writes `lab/methods.yaml`, `lab/methods/<name>/` (code, `config.yaml`, `README.md` = its page) and `lab/agents/<name>-analyst.md`; then `labpipe methods check`, `labpipe project sync`. Steps: `docs/ADDING_A_METHOD.md` |
| "we need our own agent role" | `lab/agents/<name>.md` starting with frontmatter (`name`, `role`, `description`, `capabilities`); see `lab/agents/README.md` |
| "a second project" | `labpipe project new <another folder>`: its own settings, results, container and port |

Text inside `<!-- … -->` in these files is left out (the templates keep their explanations and examples there). A file in `lab/agents/` that names no role (a typo) is reported by `labpipe project sync` and `labpipe doctor`, never dropped silently.

## After a change

`labpipe project sync`. Nothing is re-analysed. The agent tool picks up the new text in its next session.

## The project folder

```
~/labpipe-projects/pd-films/
  labpipe.yaml            marks the folder as a project: its name, the labpipe release, the updates
  backups/                what `labpipe update` and `labpipe migrate` saved before they changed something
  config/                 your settings: data folders (local.yaml), plots and report (lab.yaml), samples
  context/                what the study is about, for the postdoc: context.md, documents/
  lab/                    your additions: conventions (LAB.md), agent roles, methods, XRD references
  analysis/               results: report.html, one folder per measurement, comparison figures, postdoc runs
  manifest.json           every file found and its state
  logs/                   runs, notifications, replays
  AGENTS.md  CLAUDE.md    generated for the agents: do not edit
  .labpipe/  .claude/ …   generated: do not edit
```

- **In the container** the three folders (README → Three folders) are `/opt/labpipe` (the code,
  built into the image), `/data/<id>` (each data folder, read-only) and `/project` (this folder).
- **Updates** replace the code and the files marked "generated" here. They never touch your data,
  `context/`, `lab/` or results; a file in `config/` changes only when a release renamed something
  in it and you agree after seeing the diff (a backup is kept in `backups/`).
- **More projects**: `labpipe project new ~/labpipe-projects/<name> --data <its data folder>`.
- **Dev mode**: the labpipe repository is its own project; there the code and the project folder
  are the same folder.
