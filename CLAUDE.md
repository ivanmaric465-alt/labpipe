# Claude Code specifics

The instructions above apply. This part covers what only Claude Code provides: the extra safety layers and unattended runs.

- **Agent files**: `.claude/agents/*.md` are generated by `labpipe agents sync` from `agents/*.md` (with `harness: claude-code` in `config/local.yaml`). Edit the sources, then sync.
- **Permissions** (`.claude/settings.json`): `labpipe` commands and edits of steering files and notes are pre-approved; destructive shell commands are denied; edits of `config/local.yaml`, `config/pipeline.yaml` and `.claude/` always ask the user.
- **Guard hook** (`labpipe guard`, run before every shell command and file edit): blocks writes to raw or protected paths, shell commands naming them, and agent edits of pipeline outputs and the manifest. In unattended mode it allows only plain `labpipe` pipeline commands and writes of notes and logs.
- **Unattended runs**: the exact command is in `docs/SAFETY.md` (`claude -p --agent supervisor` with `.claude/unattended.json`, `LABPIPE_AGENT_MODE=unattended`, sandbox required). On Windows the sandbox needs WSL2.
- Never add `Edit(...)` deny rules for files labpipe itself writes: in the sandbox they block labpipe too (`docs/SAFETY.md`).
